# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added

- **Canvas presentation, behind the new off-by-default `canvas` feature** (requires `vello`; pulls no winit). `window::CanvasHost` attaches to a `<canvas>` already on a page and presents through the same blit path, `WindowApp`, `Frame` and `Event` the desktop window uses. The responsibilities invert: a desktop app hands control to `run`, whereas a page keeps its own event loop and calls `render` for a frame, `resize` when the element changes size, and `dispatch` to forward an event — which returns whether the app asked for a redraw, leaving scheduling to the page. Device acquisition is awaited rather than blocked on, so `WindowSurface` grew an async constructor with the blocking one as a wrapper over it. Only `wasm32` compiles the host, since `wgpu::SurfaceTarget::Canvas` exists nowhere else. Picking works and stays opt-in through `WindowConfig::picking`, but not by blocking: `CanvasHost` submits the pick readback and drains it once it lands, so `pick_at` can answer from a frame or two earlier rather than parking the main thread.
- **`document::FORMAT_VERSION_MAJOR` / `FORMAT_VERSION_MINOR`** — the document format version this build speaks, which was previously internal. The reader refuses a major it does not know (equality, not a floor), so it is a hard compatibility boundary between whatever writes a document and whatever reads it — worth asserting on in a build step rather than discovering as a plot that never renders. The wasm client re-exports the major as `documentFormatVersion()`.
- **`crates/hephaestus-web` ships as an npm package.** `./build.sh` assembles `dist/` — wrapper, glue, wasm, hand-written types, and a `package.json` whose version tracks the crate — which is both what the demo loads and what gets published, so the wrapper imports the glue by the same path in development and after release. `verify-dist.mjs` loads the result the way a consumer does and checks the manifest against the directory; CI runs it and reports what `npm pack` would ship. Consumers pin by exact-version CDN URL or through a bundler; the glue locates its own wasm relative to `import.meta.url`, so neither needs configuring.
- **`crates/hephaestus-web`** — the wasm render client built on `CanvasHost`: a page loads it, points it at a canvas and a `.hplot` document, and gets a plot that re-solves its layout on resize instead of stretching. Its own workspace, so it can carry a size-tuned release profile without that reaching this crate's native builds. The Rust side is deliberately thin — `render`, `resize`, `setDark`, and the two font entry points — with `ResizeObserver`, `matchMedia`, `requestAnimationFrame` and `fetch` in a JS wrapper, on the grounds that wasm bytes cost a page something and JavaScript does not. Fonts register once per page and are reused by every plot on it; light/dark derives each mode from the theme the document carried, so toggling is idempotent, and the canvas clear colour keys to the palette's paper anchor so it inverts along with the chrome. WebGPU is required — vello rasterises through compute pipelines and WebGL2 has no compute stage — so `isSupported()` is a hard gate rather than a preference.
- **`PlotView`'s `saveOnRightClick` gives a plot an ordinary image's context menu** — Save image as…, Copy image, drag-to-save. A `<canvas>` never offers these, because they come from the hit-test node being an image and a `contextmenu` handler cannot retarget the menu, so the option overlays a transparent, exactly-coincident `<img>` on the canvas and refreshes its `src` from the live frame on pointer entry, right-click mousedown and `contextmenu`. The canvas below still renders; the image above is what the menu acts on. Encoding stays lazy rather than per-frame. Every capture re-renders first, which Safari requires: it returns an opaque-black snapshot unless a render happened recently, because its drawable is consumed once composited, where Chrome and Firefox retain the presented image. The exported PNG also carries a `pHYs` chunk describing the dpi it was rendered at — a canvas writes none, so a viewer would otherwise assume 72 dpi and a plot rendered at 2× device pixels would claim twice its physical size. The rewritten bytes reach the image as a `data:` URL rather than a blob, because Safari's context menu drops its save entries for `blob:` sources.
- **The demo page shows a placeholder while the renderer starts.** Startup is dominated by GPU setup — adapter, device, and vello's compute-pipeline compilation — not by the wasm module, which fetches and instantiates in about 20 ms together, so the wait is worth signalling rather than optimising away. The placeholder is an overlay element because calling `getContext("2d")` on the canvas would make the later `getContext("webgpu")` return `null` for good. `PlotView.create` resolves only once the first frame is drawn, so a host can clear its own placeholder straight after awaiting it.
- **The wasm client draws synchronously on resize.** Assigning a canvas's `width` / `height` clears its drawing buffer, and a `ResizeObserver` callback runs after layout but before paint — so deferring the redraw to `requestAnimationFrame` let the browser paint the cleared buffer first, which read as a flicker on every step of a drag plus a frame of latency. The observer now draws in the same turn, and also takes its size from `devicePixelContentBoxSize` where available, so the backing store matches the device-pixel box exactly instead of rounding against `devicePixelRatio`.
- **`text::register_font_families`** — register a font blob and get the family names back, rather than a face count. `set_generic_family` takes names and the only place a family's name is recorded is inside the file, so a host with no system fonts — a browser, where every generic resolves to nothing until it is told otherwise — could not previously pair the two without guessing from a filename. Guessing survives until the first real font, at which point the generic silently resolves to nothing and no text draws at all. `register_font_bytes` keeps returning the face count.
- **`document::read_hints` and `DocumentHints`** — read the render hints a document carries (`background`, `size`, `dpi`) without rebuilding the composition. `WriteOptions` has always recorded them and the reader decoded and discarded them, leaving a consumer that has to choose a size before it has laid anything out with no way to ask. Decodes the head alone, so it is cheap enough to call first.

- **Markdown in every chrome text slot.** Legend titles, colorbar titles, break labels (cartesian ticks, legend keys and polar rails alike) and legend text swatches now read the `markdown` flag, so a theme that turns rich text on gets it everywhere rather than only on the title band, axis titles and strip labels. Polar titles that stamp glyphs along an arc stay plain — the rich pipeline has no per-glyph placement surface.
- **`RichTextRun` answers the metrics `TextRun` does** — `baseline_offset`, `cap_height`, `ink_top_offset` and `inked_height` — so a caller can anchor either kind of run the same way. The inked band unions the glyph ink with every block paint box, so a backgrounded block measures at the size it draws.
- **`AxisTheme::resolved_with_root`** — resolves an `AxisTheme` against a root text element, the way `Theme::resolved_axis` already did for `PerAxis`.
- **JPEG, TIFF and WebP writers** — behind the new `jpeg`, `tiff` and `webp` features, one encoder each (`jpeg-encoder`, `tiff`, `image-webp`; all pure Rust and wasm-clean). Each format offers the same three entry points as PNG: `write_*` to a path, `write_*_to` for any writer, `encode_*` for the bytes in memory. TIFF and WebP are lossless and carry alpha; TIFF takes a `TiffCompression` (deflate, LZW, PackBits, or none) and declares its alpha unassociated. JPEG has no alpha channel, so `write_jpeg` takes a `quality` (1–100) and a background `Color` to composite the buffer onto.
- **`hephaestus::image`** — the home of every raster writer, including PNG. `hephaestus::png::{write_png, encode_png, write_png_to}` continue to resolve as aliases for the entries in `image`.
- **Live window presentation** — behind the new off-by-default `window` feature (`winit`, requires `vello`). `window::run(config, app)` opens an OS window, owns the GPU device backing its swap chain, hands that device to the Vello renderer, and pumps an event loop; the app implements `WindowApp`, drawing into a `Frame` per frame and taking resize, cursor and mouse-button events through `event(&mut EventCtx, Event)`. A `Frame` carries the scene alongside the physical size and the DPI to render at, so theme lengths in pt / mm come out at the right physical size on a high-density display, and a resize schedules a frame at the new size rather than stretching the last one. Picking is opt-in per window through `WindowConfig::picking`, after which `EventCtx::pick_at` answers the id under any pixel — the pick id the host needs for hover and click without a CPU hit-test. winit stays out of the public surface: `Event`, `MouseButton` and `PresentMode` are the crate's own types. `run` is native-only; the browser is served by `CanvasHost` instead. See `examples/window.rs`.
- **Plot documents** — behind the new off-by-default `document-read` and `document-write` features (`document` enables both). `document::write_composition` captures a `PlotComposition` as a self-contained byte string and `document::read_composition` rebuilds a live one from it, so a plot can be authored in one process and drawn in another. Nothing shaped or measured is written: shaped text runs, axis and legend measures, solved layouts and every cache are functions of the output size and are rebuilt on load, with text traveling as source strings plus style descriptors. The consumer calls `render` at whatever size it has and the plot reflows — axes re-lay-out, text re-wraps, ticks recompute — rather than scaling a frozen image, which is the point of the format. `WriteOptions` carries the render hints a composition itself has no field for (`background`, `size_hint`, `dpi_hint`) plus `embed_fonts` for a consumer whose font context starts empty; `ReadContext` takes the host's own geom constructors (`with_geom`) and named formatters (`with_formatter`). Writing is strict by default: `unsupported_items` reports everything a plot carries that a document can't — an anonymous label formatter, a geom that doesn't name its kind, a track sized against another grid's track — and `write_composition` refuses with the whole list unless `WriteOptions::lossy` says to degrade them instead. Reading fails with a `DocumentError` that names what went wrong, and a document whose minor version postdates the build still reads, since unknown chunks are skipped. The two directions are separate features because a consumer only ever reads, and `document-read` compiles half the codec. Both halves are hand-rolled and dependency-free, which makes `--no-default-features --features document-write` a complete writer with no renderer at all — the one configuration that builds on rustc 1.86. See `examples/document_save.rs` and `examples/document_load.rs`.
- **`Geom::kind`** — a stable wire name for the concrete geom type behind a `Box<dyn Geom>`, which the type system otherwise carries implicitly. Every geom in the crate returns `Some`; the default is `None`, so a geom defined downstream opts in by overriding it and registering a matching constructor with `ReadContext::with_geom`. A tag names a type rather than a version — once shipped it has to keep meaning the same channels. `GeomBuilder::from_parts` is the inverse of `into_parts`, for rebuilding a geom from captured channels.
- **`Plot::add_boxed_geom` and `Plot::geoms`** — the counterpart to `remove_geom`, which already handed back a `Box<dyn Geom>`, and a borrowing iterator over every geom with its id in draw order. Alongside them, read-only accessors for the plot settings that had setters but no getters: `aspect_ratio_ref`, `is_clipped`, `tracks_identity`, `title_ref`, `subtitle_ref`, `caption_ref` and `shape_registry_ref`.
- **`Scale::with_named_format` / `set_named_format`, and `Scale::format_spec`** — a label formatter registered under a name, plus `FormatSpec` describing which of the three kinds a scale carries (`Default`, `Named`, `Custom`). A closure can't be inspected, so a name is what lets a scale's labels be reproduced in another process; an anonymous `with_format` closure stays `Custom` and cannot.
- **`Scale::try_with_bins` and `try_set_bins`** — fallible siblings of `with_bins`, returning `BinEdgeError` (`TooFew`, `NotFinite`, `NotIncreasing`) instead of panicking, for edges that arrive from data rather than from a literal. `try_set_bins` leaves the existing ladder in place when it rejects.
- **`linetype::try_pattern` and `linetype::check_pattern`** — fallible siblings of `pattern` and `validate_pattern`, returning `PatternError` (`OddLength`, `Misaligned`) for a dash pattern built from data rather than from a literal.
- **`text::font_faces_for_family`, `generic_family_names` and `set_generic_family`** — read the font files backing a family out of the font context and reinstate them, or a generic family's resolution order, somewhere else. `font_faces_for_family` returns one entry per distinct *file* rather than per face, since a collection (TTC / OTC) holds a whole family in one file and `register_font_bytes` registers every face in a file anyway.
- **`RecordingScene`, `Op` and `OwnedGlyphRun` are `PartialEq`.** Equality is op-for-op, which makes a recording usable as a test oracle over *drawing* rather than pixels — useful when the rasterizer is the variable you want to hold still. `Font` compares by face (the same bytes at the same index) rather than by blob identity, so two recordings of the same glyph run stay equal when font resolution handed each one its own blob for one file.
- **`RichTextStyleSheet::iter`, `len` and `is_empty`** — walk a sheet's named style deltas.

### Changed

- **wasm builds no longer compile wgpu's `webgl` backend.** On wasm `wgpu` exists only to serve `vello`, which rasterises through compute pipelines — and WebGL2 has no compute stage, so a WebGL adapter could never run the backend. Enabling it compiled `glow` and the GL hal into every wasm bundle to back an adapter that would be found and then fail inside pipeline creation. Only WebGPU is compiled in, and the canvas host requests only `Backends::BROWSER_WEBGPU`, so an unsupported browser fails at adapter selection with something a page can act on.
- **`EventCtx::request_redraw` schedules the frame once the handler returns**, rather than calling into the windowing backend during it. winit coalesces redraw requests anyway, so the observable behavior is unchanged; the point is that `EventCtx` no longer holds a winit type and can be shared with the canvas host.
- **The built-in rich-text sheet no longer sets a line height on `base`.** The caller's `TextStyle::line_height` was the one field the sheet overrode, which left a chrome slot unable to reach its own theme's line height without rewriting the sheet. A plain string now measures identically through both shapers. A document that wants marquee's `1.6` leading asks for it on the style it passes.
- **`RichTextRun`'s `Measure::height_at` reports the inked band** rather than the stacked line box, matching `TextRun`. A markdown slot no longer reserves the half-leading above the first line and below the last that the run never paints into.
- **Unwrapped chrome runs are memoized across frames.** Break labels and chrome titles shape at natural width and never re-break, so they cache cleanly; only the slots the layout solver re-breaks (title band, axis titles, strip labels) stay uncached. Both the measure and the draw pass read the same memo, which also makes the two structurally unable to disagree.
- Writers reject a zero width or height with `io::ErrorKind::InvalidInput` and a message naming the dimensions. A zero-area image already failed; the error is now the same shape as the wrong-buffer-length one, for every format.
- **`rust-version` is 1.86**, down from 1.88 — what this crate's own source needs. A build that pulls in `vello` or `parley` still wants 1.88, since those trees declare it; the floor exists for the renderer-free `--no-default-features --features document-write` configuration, which an R package vendoring this crate for CRAN has to hit. Building that configuration on 1.86 needs `--ignore-rust-version` today, because `parley` and `fontique` are still compiled for their text descriptors and cargo refuses on their declared floor alone, not on anything in their code.
- **`Locale` is a tag and nothing more.** It named a locale *and* described one — a decimal mark, a grouping separator, four tables of month and weekday names, AM / PM markers and a first day of week — but of those nine fields exactly one, the decimal mark, was read anywhere in the crate. Describing a locale correctly takes a CLDR-sized table, and that table belongs with whatever formats labels rather than with the renderer that draws them.

  So `Locale` carries a tag and nothing else: `Locale::EN_US`, `Locale::from("ar-EG")`, `locale.tag()`. It rides on `Theme`, reaches every `LabelFormatter` beside the value being formatted, and is written into a plot document so a consumer knows which locale a plot was for. The tag is a `Cow<'static, str>`, so the built-in constants stay compile-time values that cost no allocation while a tag obtained at runtime owns itself. It is carried verbatim — canonicalizing `ar_EG` to `ar-EG` needs the same table the type exists to avoid holding, so the two are distinct `Locale`s.
- **The default tick formatter ignores the locale.** It consulted `locale.decimal`, so `Locale::DE_DE` rendered `0,5` on a numeric axis. With no rules on the type there is nothing to consult: numbers render with a `.` decimal and temporal values as compact `YYYY-MM-DD` / `HH:MM:SS`, whatever locale is passed. An axis that should follow a locale supplies a closure through `Scale::with_format`, which receives the tag.

### Removed

- **`Locale`'s descriptive fields, and the `Weekday` enum.** `decimal`, `grouping`, `month_short`, `month_long`, `day_short`, `day_long`, `am`, `pm` and `first_dow` are gone, and `Weekday` with them — it existed only as `first_dow`'s type. `Locale` is also no longer `Copy`, since it now owns a string. Neither a struct field nor an enum can be kept resolving at its old path, so constructing a `Locale` literal, reading one of its fields, or naming `Weekday` all need changing; a tag goes in through `Locale::from` or `Locale::from_static` and comes out through `locale.tag()`.

### Fixed

- **The theme's root `text` element reaches legend text.** The legend cascade resolved titles and break labels against the concrete defaults only, so a figure-wide font, colour or `markdown` switch set on `theme.text` never landed on a legend.

## 0.1.0

First public release.

### Added

- **Scene API** — the backend-agnostic drawing surface: `SceneBuilder` (fill, stroke, images, glyph runs, meshes, layers) and `Renderer`, split so recording and vector backends need not satisfy GPU concerns. The public surface is the intersection of what Vello and Blend2D natively support.
- **Vello backend** — GPU rasterizer via wgpu, with headless render-to-buffer and an opt-in picking path that answers point queries from a parallel pick texture.
- **Layout engine** — recursive grids with `fr` / `auto` tracks, aspect-ratio `respect()`, and the `Measure` protocol for content-driven sizing.
- **Composition** — patchwork-style plot composition over a 13×16 anatomical grid, with chrome alignment across nested compositions via `Extent::TrackOf`.
- **Plot API** — `Plot` and the `PlotComposition` orchestrator, name-bound scales shared across panels, and key-based columnar diffing for identity-preserving animation.
- **Geoms** — point, line, segment, rect, ellipse, polygon, wedge, ribbon, B-spline, ribbon-B-spline, geometry, and three text geoms (mark, fit-to-box, along-path).
- **Scales** — continuous, discrete, binned, temporal, and identity families; log / sqrt / custom transforms; symmetric break control across majors and minors; locale-aware label formatting.
- **Projections** — cartesian and polar plus a `CustomProjection` hook, with edge densification so straight lines in data space curve correctly under non-linear projections.
- **Chrome and themes** — axes, legends, colorbars, facet strips, titles and captions, every element theme-driven with no hardcoded constants in the render path.
- **Text** — parley-backed shaping and layout, plus a marquee-flavoured markdown subset with inline styling, block borders, and backgrounds.
- **Optional features** — `google-fonts` for on-demand font fetching, `chrono` / `time` / `jiff` datetime interop, and `geom-wkt` / `geom-wkb` / `geom-geojson` spatial parsers.

### Notes

- `kurbo`, `peniko`, and `wgpu` types appear in the public API, so their major versions are part of this crate's semver contract. `parley` does not — text alignment is expressed with the crate's own `HAlign`.
- `blend2d`, `svg`, and `pdf` are feature placeholders with no backend code behind them yet.
